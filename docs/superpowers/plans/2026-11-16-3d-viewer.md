# 3D Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** One high-quality 3D viewer, with tools for checking work, used on the project page, on Build cards and on the landing page.

**Architecture:** The maths and labels are pure functions in `lib/model-view.ts`. A three.js "stage" (`model-stage.ts`) owns the scene, lights, camera and drawing, and takes any `Object3D`. `model-viewer.tsx` is the React shell: it loads a file or a sample, creates the stage, and draws the toolbar.

**Tech Stack:** Next.js 16, React 19, three.js 0.186 (already a dependency, loaded with `import()`), Tailwind 4, `tsx --test`, Playwright (`e2e/*.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-16-3d-viewer-design.md`

## Global Constraints

- three.js is only ever loaded with `await import(...)`, never at module top level in a file the landing page imports.
- A model file is fetched only after a press ("View in 3D") or, on the project page, as today (FIX-75).
- Colours come from the theme tokens (`--surface-2`, `--text`, `--border`); no fixed background colours.
- Buttons are `rounded-lg`, never `rounded-full` (`tests/design-guard.test.ts`).
- No database step. Never run anything against `web/.env.local` (production); use the local stack.
- Reduced motion: the model does not turn by itself.

## Review Focus

- **No WebGL** (old phone, locked-down browser, some CI Chrome builds): the viewer says 3D isn't available here and still shows the size readout; nothing throws.
- **A huge or broken file:** a parse error shows "This model couldn't be previewed"; a 300k+ triangle mesh skips the edge overlay (see-through falls back to plain transparency) so the tab doesn't freeze.
- **A single-part model:** the explode control isn't shown.
- **A phone:** an up-down drag on the viewer scrolls the page.
- **A flat or zero-size model** (a 2D outline exported as STL): the camera still frames it; size shows 0 for the flat axis, not NaN.

### Task 1: The maths and labels

**Files:** Create `web/src/lib/model-view.ts`; Test `web/tests/model-view.test.ts`

**Interfaces (produces):**
- `type V3 = [number, number, number]`
- `VIEWS: readonly { id: ViewId; label: string; dir: V3 }[]` with ids `"angled" | "front" | "side" | "top"`, labels `Angled`, `Front`, `Side`, `Top`
- `cameraFor(id: ViewId, radius: number): V3` — the camera's position for a model of that radius, centred on the origin
- `fmtDim(n: number): string` — `0` → `"0"`, `<10` two decimals, `<100` one, else whole; trailing zeros dropped
- `sizeLabel(ext: string, size: V3): { text: string; unit: string }` — width × depth × height. `glb`/`gltf` are metres: shown in `mm` when the largest side is under 1 m, else `m`. `3mf` is `mm`. Anything else: unit `"file units"`.
- `trianglesLabel(n: number): string` — `"312 triangles"`, `"48k triangles"`, `"1.2M triangles"`
- `explodeOffsets(centers: V3[], amount: number, radius: number): V3[]` — each part moves away from the average centre by `amount × radius × 0.9`; a part sitting on the average centre moves straight up
- `EDGE_LIMIT = 300_000` (triangles)

- [x] Write the tests: `cameraFor("top", 2)` looks down (x and z near 0, y > 0) and every view sits the same distance out; `fmtDim` on 0, 4.2, 45.25, 120.4, NaN (→ `"0"`); `sizeLabel("glb",[0.12,0.045,0.08])` → `120 × 80 × 45`, `mm`; `sizeLabel("glb",[2,1,1.5])` → `2 × 1.5 × 1`, `m`; `sizeLabel("stl",[20,20,20])` → `20 × 20 × 20`, `file units`; `trianglesLabel` on 312, 48_200, 1_240_000; `explodeOffsets` with amount 0 is all zeros, pushes two parts in opposite directions, and moves a centred part up.
- [x] Run `npx tsx --test tests/model-view.test.ts`: fails (module missing).
- [x] Implement.
- [x] Run again: passes.
